== Exercise: Create your Gitea organization and seed lab repositories

Lab automation starts **Gitea** and normally creates the **user account** `student` (`student_username` / `student_password` in ConfigMap `demo-userinfo-gitea`).
If sign-in fails, run the ensure-user helper below (uses Secret `gitea-admin`).
You create the **Organization** and **repositories** you will use for the rest of the workshop, then seed them from operator-prepared **templates** under Gitea org `workshop-templates`.

=== Conventions

|===
|Item |Value

|Your organization
|`lw-student` (`student_gitea_org`)

|Application repo

=== A. Discover Gitea, ensure your user, and create the organization

Lab install creates the Gitea account `student` when Job `gitea-student-repo-seed` runs. Confirm the URL and password from the ConfigMap, then ensure the account exists before signing in.

Discover the Gitea URL (do **not** paste a hardcoded hostname):

[source,bash,role=execute]
----
oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='gitea_url={.data.gitea_url}{"\n"}student_username={.data.student_username}{"\n"}'
----

Expect `student_username=student`. Ensure that user can sign in (no-op if the seed Job already created the account; otherwise creates/updates via workshop admin Secret `gitea-admin`):

[source,bash,role=execute]
----
export STUDENT_USER=student
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"

oc -n gitea get configmap gitea-student-repo-seed \
  -o jsonpath='{.data.learner-ensure-gitea-user\.sh}' > /tmp/learner-ensure-gitea-user.sh
chmod +x /tmp/learner-ensure-gitea-user.sh
/tmp/learner-ensure-gitea-user.sh
----

The script prints **Open:** `<gitea_url>`. Open that URL in your browser and sign in as `student` with `student_password` from `demo-userinfo-gitea` (same password the script used).

. Click **+** → **New Organization**
. Set **Organization Name** exactly to *`lw-student`* (must match `student_gitea_org`)
. Visibility: **Public** → **Create Organization**

=== B. Create empty repositories

Under organization *`lw-student`*:

. **+** → **New Repository** (or **New Repository** from the org page)
. Name: *`spring-boot-lw-poc`* — leave **Initialize repository** unchecked (empty repo) → **Create**
. Repeat for *`gitops-spring-boot-lw-poc`* (stage GitOps; also empty / no README)
. Repeat for *`gitops-prod-spring-boot-lw-poc`* (prod GitOps; also empty / no README)

=== C. Seed from workshop templates

Operator Job `gitea-student-repo-seed` already published prepared trees under `workshop-templates/`. Copy that content into **your** repos:

[source,bash,role=execute]
----
export STUDENT_USER=student
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"

oc -n gitea get configmap gitea-student-repo-seed \
  -o jsonpath='{.data.learner-seed-from-templates\.sh}' > /tmp/learner-seed.sh
chmod +x /tmp/learner-seed.sh
/tmp/learner-seed.sh
----

The script also adds workshop user `gitea-admin` to the org’s **Owners** team so Module 3 RHDH `publish:gitea` can create repositories under *`lw-student`*.

Confirm:

[source,bash,role=execute]
----
oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_repo_url}{"\n"}{.data.template_app_repo_url}{"\n"}'
curl -sk -o /dev/null -w "%{http_code}\n" \
  "$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')"
----

Expect HTTP `200` on the app remote (anonymous clone works for public repos). Open `lw-student/spring-boot-lw-poc` in Gitea and confirm `pom.xml` is at the repository root.
