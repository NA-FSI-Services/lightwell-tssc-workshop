= 1.1 Verify Hummingbird
:source-highlighter: rouge
:toc:
:toclevels: 2

Track 1 starts on a *published* Project Hummingbird / Red Hat Hardened Images runtime — not a Universal Base Image (UBI) you already trust from muscle memory, and not an image this cluster mirrored for you.

In this module you discover the workshop pin from cluster userinfo, complete the incomplete ConfigMap snippet (placeholders fail the Check), and run `cosign verify` against that *published* digest. You do *not* run `oc-mirror` yet. That is xref:module-02-hummingbird-mirror.adoc[1.2].

This claim is *not* the Hummingbird factory (Fedora / Konflux on the inside). Consultants consume a signed catalog image.

== Learning objectives

By the end of this module, you will be able to:

* Discover the scored Hummingbird pull spec from ConfigMap userinfo (do not invent a tag from memory)
* Fill a verify snippet so no `REPLACE_ME_*` remains
* Run `cosign verify` against the *published* digest you recorded
* Explain that the catalog index may list other architectures; this Check is amd64 only

== Why verify before you mirror

UBI is a general-purpose base. Red Hat Hardened Images (`registry.access.redhat.com/hi/…`) are a *minimal, signed* runtime: smaller attack surface, no package manager in the image, built for production constraints.

A PoV that “uses Hummingbird” but never checks the signature is a story, not a supply chain. 1.1 proves the *published* coordinate. 1.2 copies that trust into the cluster dest. Track 3 is when application `FROM` switches — not here.

== Discover the published pin

Do *not* paste a digest from chat, a slide, or this page’s narrative. The live pin is userinfo.

.Read the source pull spec (what you verify in 1.1 and pin in 1.2)
[source,bash,role=execute]
----
oc -n lightwell-repo get configmap demo-userinfo-lightwell-repo \
  -o jsonpath='{.data.hummingbird_source_pullspec}{"\n"}'
----

.Record the amd64 manifest digest (callout — the Check does not inspect architectures)
[source,bash,role=execute]
----
oc -n showroom get configmap demo-userinfo-showroom \
  -o jsonpath='{.data.hummingbird_amd64_manifest}{"\n"}{.data.hummingbird_source_registry}{"\n"}'
----

Keep both values. The pull spec’s `@sha256:…` is the *index* (it may list more than amd64). `hummingbird_amd64_manifest` is the platform digest this workshop scores. Dual-arch hands-on is out of this lab.

== Worked example (not the Check)

The following verifies a *different* image with a *non-Red Hat* key URL. If your Check uses this block unchanged, it fails.

[source,bash]
----
# Worked example ONLY — ubi-minimal + a key that is not Red Hat Hardened Images.
cosign verify \
  --key https://example.invalid/not-redhat-hardened-images.pub \
  --insecure-ignore-tlog \
  registry.access.redhat.com/ubi9/ubi-minimal:latest
----

== Your change: complete the verify ConfigMap

The scored object is ConfigMap `stub-01-hummingbird-verify` in `lightwell-repo` (not a file you invent only in Showroom home). Extract it, replace every `REPLACE_ME_*` with values you discovered (pull spec from userinfo; key URL from the Hardened Images verify documentation below), then write it back. Leave a placeholder and the Check fails. Do not copy the ubi-minimal worked example.

.Extract the incomplete seed
[source,bash,role=execute]
----
oc -n lightwell-repo get configmap stub-01-hummingbird-verify \
  -o jsonpath='{.data.published-verify\.sh}' > ~/track-1-1-published-verify.sh
----

The seed looks like this (placeholders fail):

[source,bash]
----
#!/usr/bin/env bash
set -euo pipefail
# Scored snippet — not paste-identical to the worked example.
export HUMMINGBIRD_PUBLISHED='REPLACE_ME_HUMMINGBIRD_PULLSPEC'
cosign verify \
  --key REPLACE_ME_COSIGN_KEY \
  --insecure-ignore-tlog \
  "${HUMMINGBIRD_PUBLISHED}"
----

Red Hat documents key-based verify for Hardened Images (not in-cluster RHTAS Fulcio — that is Track 5, on *your* app image). On non-RHEL hosts the published pattern is:

* `--key https://security.access.redhat.com/data/63405576.txt`
* `--insecure-ignore-tlog`

That host is Red Hat’s key distribution, not `github.com`. If the fetch is blocked on a locked-down claim, stop and tell an instructor — do not invent a Fulcio identity for this Check.

See link:https://docs.redhat.com/en/documentation/red_hat_hardened_images/1-latest/html/build_and_deploy_secure_minimal_containers_with_red_hat_hardened_images/run-containerized-tools-with-red-hat-hardened-images[Verify the integrity of Red Hat Hardened Images].

.Write the snippet back to the ConfigMap (after you filled the placeholders)
[source,bash,role=execute]
----
chmod +x ~/track-1-1-published-verify.sh
oc -n lightwell-repo create configmap stub-01-hummingbird-verify \
  --from-file=published-verify.sh=$HOME/track-1-1-published-verify.sh \
  --dry-run=client -o yaml | oc apply -f -
grep -E 'REPLACE_ME' ~/track-1-1-published-verify.sh && echo 'STILL HAS PLACEHOLDERS' || echo 'placeholders gone'
----
