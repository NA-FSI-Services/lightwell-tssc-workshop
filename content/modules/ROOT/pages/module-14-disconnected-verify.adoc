= 5.3 Disconnected verify
:source-highlighter: rouge
:toc:
:toclevels: 2

On this page you prove that the application digest also carries a signature you can verify with a public key, without calling Fulcio.

Track 5 is sign and attest. This is the third page. xref:module-12-sign-keyless.adoc[5.1 Sign] already signed that digest with Trusted Artifact Signer. You generate a cosign key pair on the Showroom terminal, run `cosign sign --key`, and then `cosign verify --key`. The cluster stays on the network. You are practicing the procedure a disconnected plant uses, which is a key you can carry. You are not building a physical air gap. Mirrored TUF for keyless verifiers, and a simulated media drop, live in xref:appendix-disconnected-playbook.adoc[Appendix: disconnected transfer].

== Why this control exists

Keyless signing needs Fulcio when the signature is created, and a TUF root when it is verified. A plant that cannot reach Fulcio at verify time still needs a public key it controls. You add that second signature here, on the same digest. The keyless signature stays on the image.

Native `ImagePolicy` `signedEmail` cannot hold the 5.1 Kubernetes service-account URI. xref:module-15-gitops-admission.adoc[6.1 GitOps + admission] therefore renders CRI-O policy as `policyType: PublicKey` from the PEM you publish. That PEM is ConfigMap `lab-cosign-pubkey` in namespace `tssc-admission`. xref:module-12-sign-keyless.adoc[5.1 Sign] draws the keyless column. This page is the other signature: `~/lab-trust/cosign.key` signs, and `cosign.pub` is what admission will trust.

In a customer engagement, a disconnected plant verifies with keys, and it keeps a mirrored TUF root for any artifact that was signed keylessly. You generate the pair on this terminal and sign the digest you already built. Red Hat does not operate a data diode on this cluster. An empty `COSIGN_PASSWORD` is for this non-interactive lab terminal. A customer plant uses a real passphrase.

== Learning objectives

By the end of this module, you will be able to:

* Generate a cosign key pair under `/home/lab-user/lab-trust` and sign the application digest with `--key` and `--tlog-upload=false`
* Verify that digest with `cosign verify --key`
* Publish `cosign.pub` to ConfigMap `lab-cosign-pubkey` so 6.1 can render ImagePolicy
* Explain that a Lightwell library signature is a different layer from this application key

== Your change

Generate the key pair in `~/lab-trust` if `cosign.key` is not already there. `export HOME=/tmp/lab-home` exists so `cosign login` does not write a Docker config into the real home directory. The `--key` path and the ConfigMap `--from-file` path stay on `/home/lab-user/lab-trust`, because a tilde would follow the temporary `HOME`. `--tlog-upload=false` keeps this signature off the public Rekor log. That is the disconnected procedure: the signature travels with the digest, and verify uses `--insecure-ignore-tlog` on the next step.

ImagePolicy `signedEmail` cannot store a service-account URI. The public key is what 6.1 will render. Success is `cosign.pub` on disk, `cosign sign` exiting 0, and ConfigMap `lab-cosign-pubkey` in namespace `tssc-admission` holding that PEM. Put `HOME` back to `/home/lab-user` before the Check.

.Sign with the key and publish the public key
[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_build_namespace}')"
IMAGE="image-registry.openshift-image-registry.svc:5000/${BUILD_NS}/spring-boot-lw-poc:latest"
mkdir -p ~/lab-trust
cd ~/lab-trust
if [[ ! -f cosign.key ]]; then
  COSIGN_PASSWORD="" cosign generate-key-pair
fi
export HOME=/tmp/lab-home
mkdir -p "${HOME}"
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000
COSIGN_PASSWORD="" cosign sign --key /home/lab-user/lab-trust/cosign.key \
  --tlog-upload=false \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE}"
# ImagePolicy signedEmail cannot be a SA URI. Publish the public key for 6.1.
oc -n tssc-admission create configmap lab-cosign-pubkey \
  --from-file=cosign.pub=/home/lab-user/lab-trust/cosign.pub \
  --dry-run=client -o yaml | oc apply -f -
# Tilde follows HOME. Put the real home back before the Check (or use /home/lab-user/lab-trust).
export HOME=/home/lab-user
----

== Check

Verify the same application tag with `/home/lab-user/lab-trust/cosign.pub`. `--insecure-ignore-tlog` matches the sign, which did not upload a transparency-log entry. Success is exit code 0 on your application digest. The 5.1 keyless signature has to remain verifiable. Stripping the Fulcio signature fails that later use.

.Verify with the public key
[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_build_namespace}')"
IMAGE="image-registry.openshift-image-registry.svc:5000/${BUILD_NS}/spring-boot-lw-poc:latest"
export HOME=/home/lab-user
LAB_TRUST=/home/lab-user/lab-trust
test -f "${LAB_TRUST}/cosign.pub"
test ! -f /home/lab-user/example-not-lab-trust/demo.pub || echo 'example path present (ok if unused)'
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000
cosign verify --key "${LAB_TRUST}/cosign.pub" \
  --insecure-ignore-tlog \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE}"
----
