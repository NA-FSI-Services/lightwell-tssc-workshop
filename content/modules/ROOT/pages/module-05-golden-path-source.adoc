= 3.1 Golden-path source
:source-highlighter: rouge
:toc:
:toclevels: 2

On this page you prove that the Java application lives on a git remote you own, on the Gitea inside this cluster.

Track 3 is application source. This is the first of its three pages. Operator templates stay in organization `workshop-templates`. The scored remote is `lw-student/spring-boot-lw-poc`. You create that organization, create three empty repositories, and run the seed script. The script also adds `renovate-bot`, which xref:module-07-live-renovate.adoc[3.3 Live Renovate] needs. xref:module-06-bind-base-deps.adoc[3.2 Bind base and deps] is where the Dockerfile `FROM` changes.

== Why this control exists

Pins, `FROM` lines, pipeline YAML, and GitOps remotes count only when a later Check can see them on a remote the learner owns. The golden path copies a prepared tree into organization `lw-student`. From that commit on, you own the history.

Lightwell Network and Lightwell Clearinghouse Premier do not host application source. They supply the GAVs you commit on the next page and that Renovate bumps on the page after that. A Premier member remediation still needs this remote.

Red Hat Developer Hub Software Template `lightwell-java-service` can publish into the same organization. It is optional. `lightwell-python-service` is the same idea, with `requirements.txt` at the repository root. That template is not enabled on this cluster. This Check is the seed script.
====

In a customer engagement the git host is GitHub, GitLab, or Bitbucket, and the copy is often a Developer Hub software template. This lab uses in-cluster Gitea so the exercise has no `github.com` remote. MintMaker, in that same customer conversation, maps to the Renovate bot you meet on 3.3.

== Learning objectives

By the end of this module, you will be able to:

* Create organization `lw-student` and the empty application and GitOps repositories on in-cluster Gitea
* Seed those repositories from the workshop templates, including the `renovate-bot` collaborator
* Confirm `student_repo_url` serves `pom.xml` at the repository root
* Map a Developer Hub software template in a customer engagement to this seed

== The Gitea coordinates

ConfigMap `demo-userinfo-gitea` in namespace `gitea` holds the URLs. `gitea_url` is the console. `student_username` is `student`. `student_gitea_org` is `lw-student`. `student_repo_url` is the scored application remote. `template_app_repo_url` is the operator tree you copy from. The password is the value of key `student_password`. Leave that value out of Git and out of screenshots.

Success is those fields, with user `student` and org `lw-student`.

[source,bash,role=execute]
----
oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='gitea_url={.data.gitea_url}{"\n"}user={.data.student_username}{"\n"}org={.data.student_gitea_org}{"\n"}app={.data.student_repo_url}{"\n"}templates={.data.template_app_repo_url}{"\n"}password={.data.student_password}{"\n"}'
----

The seed Job may already have created the `student` account. The ensure script is a no-op when the account exists. Success is a script that exits 0.

.Ensure the Gitea user can sign in
[source,bash,role=execute]
----
export STUDENT_USER=student
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"

oc -n gitea get configmap gitea-student-repo-seed \
  -o jsonpath='{.data.learner-ensure-gitea-user\.sh}' > /tmp/learner-ensure-gitea-user.sh
chmod +x /tmp/learner-ensure-gitea-user.sh
/tmp/learner-ensure-gitea-user.sh
----

Open `gitea_url` and sign in as `student` with that password value.

The block below is a clone of the wrong remote. A `student_repo_url` that still points at GitHub, or at `workshop-templates`, fails the Check.

[source,bash]
----
# Worked example ONLY — not the scored remote.
git clone https://github.com/example/spring-boot-lw-poc.git
# or: git clone <template_app_repo_url>   # workshop-templates, not lw-student
----

== Your change

In Gitea, open *+* and choose *New Organization*. The name is exactly `lw-student`. Visibility is *Public*. Create the organization.

// VISUAL: https://github.com/NA-FSI-Services/lightwell-tssc-workshop/issues/61
image::gitea-new-org-lw-student.png[Gitea New Organization form with name lw-student,width=700,link=self,window=blank]

The capture is that form after the name is filled. The organization name is the string the later Checks look up.

Under `lw-student`, create three empty repositories. Leave the README checkbox clear. Initializing a repository puts a commit on it before the seed, and the seed expects an empty remote.

* `spring-boot-lw-poc` is the application.
* `gitops-spring-boot-lw-poc` is the stage GitOps remote.
* `gitops-prod-spring-boot-lw-poc` is the production GitOps remote.

The seed script copies the template tree and adds `renovate-bot` as a write collaborator on the application repository. Success is a script that exits 0.

.Seed from the templates
[source,bash,role=execute]
----
export STUDENT_USER=student
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"

oc -n gitea get configmap gitea-student-repo-seed \
  -o jsonpath='{.data.learner-seed-from-templates\.sh}' > /tmp/learner-seed.sh
chmod +x /tmp/learner-seed.sh
/tmp/learner-seed.sh
----

== Check

Success is HTTP `200` on `student_repo_url`, and a repository root that contains `pom.xml`. The default `<commons.lang3.version>` is still the affected upstream `3.14.0`. The remediated pin is the next page. `3.18.0` would already be the wrong fix. `lightwell-pins.properties` is still the stale seed that 3.3's bot updates.

[source,bash,role=execute]
----
oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_repo_url}{"\n"}{.data.template_app_repo_url}{"\n"}'
curl -sk -o /dev/null -w "%{http_code}\n" \
  "$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')"
----

Open `lw-student/spring-boot-lw-poc` and confirm `pom.xml` is at the repository root.
