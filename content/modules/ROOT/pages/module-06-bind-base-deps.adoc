== Why this control exists

Later builds, SBOMs, and VEX read the pins that are in git. The dest Hummingbird digest from Track 1 and the Lightwell Network Remediated GAV from Track 2 become the application's declared inputs on this page. A runtime `FROM` that is still UBI rebuilds the untrusted seed. A pin that lives only in an unused profile leaves the default on the affected line.

The seed stays on UBI so this page is a real edit. If the template already said `FROM` Hummingbird, Track 3 would be a screenshot of someone else's pin.

== Your change

Edit the clone at `/tmp/spring-boot-lw-poc`.

Change the runtime stage `FROM`. Leave the `AS build` line on UBI. The runtime line is the dest host, the path `hi/openjdk`, and the digest from `DEST_PULLSPEC`. A line that contains `hummingbird-mirror`, `registry.access.redhat.com`, or `:latest` fails the Check.

Change the default `<commons.lang3.version>` in `pom.xml` to `3.14.0.rhlw-00001`. You already practiced this on ConfigMap `stub-04-remediated-pin`. This commit is the scored git copy. A profile that is never activated leaves the default on `3.14.0`, and that default fails the Check.

Leave `lightwell-pins.properties` as the seed wrote it.

A Showroom shell has no TTY for an HTTPS password prompt, and a fresh clone may have no author identity. The next block sets both on this repository. A later Showroom restart stores the same author and Gitea credentials in `~/.gitconfig`, so later modules can keep `git commit` and `git push origin HEAD` as written. The password is interpolated into the remote URL for this push. It does not belong in a committed file.

.Set author and credentials on this clone
[source,bash,role=execute]
----
cd /tmp/spring-boot-lw-poc
git config user.name student
git config user.email student@workshop.local
: "${STUDENT_USER:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_username}')}"
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
hostpath="$(git remote get-url origin)"
hostpath="${hostpath#https://}"
hostpath="${hostpath#http://}"
git remote set-url origin "https://${STUDENT_USER}:${STUDENT_PASS}@${hostpath}"
----

Success of the commit is a push of `Dockerfile` and `pom.xml` only.

.Commit the runtime FROM and the default pin
[source,bash,role=execute]
----
cd /tmp/spring-boot-lw-poc
git add Dockerfile pom.xml
git status
git diff --cached
git commit -m "Bind dest Hummingbird runtime and Lightwell default pin"
git push origin HEAD
----

== Check

Read the files from `HEAD`, so you are looking at the commit you pushed. Success is three facts. The runtime `FROM` is the dest registry, `hi/openjdk`, and a digest. The default pom property is `3.14.0.rhlw-00001`. `lightwell-pins.properties` is still the stale seed.

[source,bash,role=execute]
----
cd /tmp/spring-boot-lw-poc
git fetch
git show HEAD:Dockerfile | grep -E '^FROM '
git show HEAD:pom.xml | grep -A1 commons.lang3.version | head -20
git show HEAD:lightwell-pins.properties
----
