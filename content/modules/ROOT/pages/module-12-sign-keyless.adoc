= 5.1 Sign (keyless)
:source-highlighter: rouge
:toc:
:toclevels: 2

On this page you prove that the application image you built carries a keyless signature from Red Hat Trusted Artifact Signer, and that `cosign verify` accepts it.

Track 5 is sign and attest. This is the first of its three pages. You sign the application digest from xref:module-11-build-sbom.adoc[4.4 Build and SBOM]. The Hummingbird base already has Red Hat's key, from Track 1. Lightwell already signed the libraries. This signature is the application's. The seeded pipeline includes Task `cosign-sign-keyless`. The PipelineRun still has placeholders until you fill the in-cluster Fulcio, Rekor, and TUF URLs. xref:module-14-disconnected-verify.adoc[5.3 Disconnected verify] adds a second, key-based signature on the same digest. Keyless alone is not the end of Track 5.

== Why this control exists

Integrity of the application image is a signature on the digest you built. The pipeline service account presents an OIDC token. Fulcio issues a short-lived certificate. Rekor records the signature. TUF distributes the trust root. `cosign verify` accepts that identity: the pipeline service account in the build namespace, issued by `https://kubernetes.default.svc`.

The URLs inside the build namespace are the in-cluster Services, `fulcio_internal_url` and its siblings on ConfigMap `demo-userinfo-rhtas`. After 4.3 the build namespace cannot reach the HTTPS Routes. The Route hints (`fulcio_url_hint` and its siblings) are for the Showroom `cosign verify` only. A verify that uses the Hummingbird key, or a fake issuer, fails the Check. Admission in Track 6 still needs the public key from 5.3, because native ImagePolicy cannot store this service-account URI. Keep both signatures.

Lightwell Network and Lightwell Clearinghouse Premier sign dependencies. They do not sign this application digest. Premier does not replace Trusted Artifact Signer.

== Learning objectives

By the end of this module, you will be able to:

* Fill the PipelineRun with the in-cluster Fulcio, Rekor, and TUF URLs and get `cosign-sign-keyless` to Succeeded
* Run `cosign verify` on the application digest with the pipeline service-account identity
* Record that digest for Track 6
* Leave the key-based `cosign sign --key` for 5.3

== The signer URLs

Success is `cosign` on `PATH`, then the signing model and both URL families: internal Services for the pipeline, and Route hints for the Showroom verify. Confirm the hints against the live Routes. A PipelineRun that still contains `apps.<domain>` fails the sign task.

.Read the RHTAS URLs
[source,bash,role=execute]
----
command -v cosign
oc -n trusted-artifact-signer get configmap demo-userinfo-rhtas \
  -o jsonpath='{.data.signing_model}{"\n"}{.data.fulcio_internal_url}{"\n"}{.data.rekor_internal_url}{"\n"}{.data.tuf_internal_url}{"\n"}{.data.fulcio_url_hint}{"\n"}{.data.rekor_url_hint}{"\n"}{.data.tuf_url_hint}{"\n"}'
oc -n trusted-artifact-signer get routes
----

The block below is `cosign verify` against a different issuer and a different image. Using it as the scored verify fails the Check.

[source,bash]

# Worked example ONLY — fake issuer/subject. Do not use as the scored verify.

  --certificate-oidc-issuer='https://example.invalid/oidc' \
  image-registry.openshift-image-registry.svc:5000/example/not-your-app:latest

== Check

Verify the application tag `spring-boot-lw-poc:latest` in the build namespace. The identity is the pipeline service account in that namespace. The issuer is the Kubernetes API. Showroom uses the Route hints for TUF and Rekor, because this shell is outside the build NetworkPolicy. `HOME` is `/tmp/lab-home` so `cosign login` does not write a Docker config into the real home directory.

If verify fails, read the SAN from the Rekor entry or from the `cosign verify` error. The identity regexp below is the one this cluster's pipeline service account presents.

Success is exit code 0, and a verification block for your application digest.

.Verify the application digest
[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_build_namespace}')"
TUF="$(oc -n trusted-artifact-signer get configmap demo-userinfo-rhtas -o jsonpath='{.data.tuf_url_hint}')"
REKOR="$(oc -n trusted-artifact-signer get configmap demo-userinfo-rhtas -o jsonpath='{.data.rekor_url_hint}')"
IMAGE="image-registry.openshift-image-registry.svc:5000/${BUILD_NS}/spring-boot-lw-poc:latest"
mkdir -p /tmp/lab-home
export HOME=/tmp/lab-home
cosign initialize --mirror="${TUF}" --root="${TUF}/root.json"
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000
cosign verify \
  --rekor-url="${REKOR}" \
  --certificate-identity-regexp="^https://kubernetes.io/namespaces/${BUILD_NS}/serviceaccounts/pipeline$" \
  --certificate-oidc-issuer="https://kubernetes.default.svc" \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE}"
----

Record the digest. Track 6 promotes it.

* 5.3 adds a key-based signature on the same digest. Track 6 admission needs that public key.
