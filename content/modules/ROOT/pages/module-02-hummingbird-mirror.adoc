= 1.2 Mirror into the trust boundary
:source-highlighter: rouge
:toc:
:toclevels: 2

On this page you prove that the Hummingbird image you verified in the public catalog now sits on this cluster's registry, and that `cosign` still accepts its signature there.

Track 1 is the base. This is the second page. xref:module-01-hummingbird-verify.adoc[1.1 Verify Hummingbird] checked the published pin. The Nexus Docker repository `hummingbird-mirror` starts empty. You finish the ImageSet, start Job `oc-mirror-learner`, and verify the dest pull spec.

== Why this control exists

Later builds, GitOps, and admission pull the runtime base from inside the enterprise. The coordinate they use is this internal dest, and you can still verify it. You run the mirror so the signature arrives with the image.

In a customer engagement, a bastion host runs `oc-mirror` into the customer's registry. On this cluster the dest is in-cluster Nexus, hosted Docker repository `hummingbird-mirror`, exposed by Route `registry-lightwell-repo`. The Route host is specific to your cluster. You read it from userinfo. You still write the ImageSet, and you still start the run.

== Learning objectives

By the end of this module, you will be able to:

* Put the Hummingbird pull spec from userinfo into `ImageSetConfiguration`
* Start Job `oc-mirror-learner` and read the dest pull spec from its signature-copy log
* Verify that dest pull spec with the same Red Hat Hardened Images key as 1.1

== The empty dest

ConfigMap `demo-userinfo-lightwell-repo` in namespace `lightwell-repo` holds the dest coordinates. Four fields matter. `dest` is the Route host. `repo` is the Nexus Docker repository name, `hummingbird-mirror`. `docker` is `docker://` plus that host, which is the destination the Job already uses. `pre_mirror` is `false` while the scored image is still absent.

Success is those four lines, with `pre_mirror=false`.

.Read the dest coordinates
[source,bash,role=execute]
----
oc -n lightwell-repo get configmap demo-userinfo-lightwell-repo \
  -o jsonpath='dest={.data.dest_registry_host}{"\n"}repo={.data.dest_registry_repo}{"\n"}docker={.data.dest_registry_docker}{"\n"}pre_mirror={.data.oc_mirror_pre_stage_scored_image}{"\n"}'
----

The file you finish is an `ImageSetConfiguration`, API `mirror.openshift.io/v2alpha1`. It tells `oc-mirror` which images to copy. On this cluster it lives in ConfigMap `imageset-configuration`, same namespace, key `imageset-config.yaml`. The seed names one additional image, and that name is still the placeholder `REPLACE_ME_HUMMINGBIRD_PULLSPEC`.

Success is a short YAML document that still contains `REPLACE_ME_HUMMINGBIRD_PULLSPEC`.

.Read the scored ImageSet
[source,bash,role=execute]
----
oc -n lightwell-repo get configmap imageset-configuration \
  -o jsonpath='{.data.imageset-config\.yaml}'
----

ConfigMap `oc-mirror-tooling` in the same namespace holds a worked example on key `example-imageset.yaml`. That example names `ubi9/ubi-minimal`. The scored file is `imageset-config.yaml` on ConfigMap `imageset-configuration`. The Check requires the Hummingbird pull spec from userinfo. An ImageSet that still names `ubi-minimal` fails the Check, including a paste of this example over the scored key.

.Read the worked example
[source,bash,role=execute]
----
oc -n lightwell-repo get configmap oc-mirror-tooling \
  -o jsonpath='{.data.example-imageset\.yaml}'
----

[source,yaml]
----
# Worked example ONLY — ubi-minimal. The scored ImageSet must be the Hummingbird digest pin.
kind: ImageSetConfiguration
apiVersion: mirror.openshift.io/v2alpha1
mirror:
  additionalImages:
    - name: registry.access.redhat.com/ubi9/ubi-minimal:latest

== Your change

Read the pull spec you verified on 1.1. Success is one line: `registry.access.redhat.com`, `hi/openjdk`, and `@sha256:`. That digest is the image index. The amd64 manifest you recorded beside it is a different sha256. The ImageSet uses this pull spec.

.Read the source pull spec
[source,bash,role=execute]
----
oc -n lightwell-repo get configmap demo-userinfo-lightwell-repo \
  -o jsonpath='{.data.hummingbird_source_pullspec}{"\n"}'
----

Edit ConfigMap `imageset-configuration` in namespace `lightwell-repo`. Set `mirror.additionalImages[0].name` to that pull spec. The command is `oc -n lightwell-repo edit configmap imageset-configuration`. Change that `name` line. Leave the rest of the key in place.

The seed looks like this:

[source,yaml]
----
kind: ImageSetConfiguration
apiVersion: mirror.openshift.io/v2alpha1
mirror:
  additionalImages:
    - name: REPLACE_ME_HUMMINGBIRD_PULLSPEC
----

The ImageSet stays a single `additionalImages` entry. The Job, in the next section, mirrors that `name` and then copies the signatures. You change the pull spec here.

== Run oc-mirror

`oc-mirror` is already on the Showroom `PATH`. The scored run is Job `oc-mirror-learner`. The Job manifest is key `job.yaml` on ConfigMap `oc-mirror-tooling`. That manifest already mounts the dest credentials and the workspace volume. You create the Job from that key, as stored. Provision leaves the Job uncreated until you do.

The Job has two containers. The init container `oc-mirror` copies the image onto dest. The stored command mirrors that image and leaves `--remove-signatures` out of the arguments. The signature tags are the next container: `copy-signatures` runs `cosign copy` from the published pin to the dest pull spec and writes `.sig`, `.att`, and `.sbom` tags beside the image. Nexus stores those objects as tags.

If a previous attempt still owns the name, delete it first. Success is `job.batch/oc-mirror-learner created`.

.Create the learner Job
[source,bash,role=execute]
----
oc -n lightwell-repo delete job oc-mirror-learner --ignore-not-found
oc -n lightwell-repo get configmap oc-mirror-tooling \
  -o jsonpath='{.data.job\.yaml}' | oc create -f -
----

The mirror and the signature copy can take several minutes. Success is `condition met` for `complete`. The wait allows 20 minutes.

.Wait for the Job
[source,bash,role=execute]
----
oc -n lightwell-repo wait --for=condition=complete job/oc-mirror-learner --timeout=20m
----

Read both containers. The init container `oc-mirror` is the image copy. The container `copy-signatures` is the tag copy.

The `oc-mirror` log prints two lines that are expected for this ImageSet. The `name` you set is one pull spec: the tag `21-runtime` and the index digest from 1.1. The warning includes `has both tag and digest : using digest to pull, but tag only for mirroring`. The next line says `No images by digests were mirrored. Skipping IDMS generation.` IDMS is an ImageDigestMirrorSet, the object that would redirect a later digest pull to a mirror. This ImageSet is mirrored under the tag, so `oc-mirror` skips that object. The copy still used the index digest from 1.1.

In the `copy-signatures` log, success is a line that starts with `DEST_PULLSPEC=`. The value is the dest host, the path `hi/openjdk`, the tag, and the same index digest as the published pin. Copy that whole line. The repository name `hummingbird-mirror` does not appear in it. The Check is `cosign verify` on that dest pull spec.

.Read the Job logs
[source,bash,role=execute]
----
oc -n lightwell-repo logs job/oc-mirror-learner -c oc-mirror
oc -n lightwell-repo logs job/oc-mirror-learner -c copy-signatures
----

== Check

Verify the dest pull spec with the same Red Hat Hardened Images public key as 1.1. Paste the `DEST_PULLSPEC=` value into the variable below. Dest TLS is the lab registry, so the command allows an insecure registry. `--insecure-ignore-tlog` skips the transparency log, and this `cosign` warns that it skipped the log.

Success is the same two checks, printed for the dest host: the cosign claims were validated, and the signatures were verified against the specified public key.

[source,bash]
----
# Fill DEST_PULLSPEC from the copy-signatures log (DEST_PULLSPEC=...).
export DEST_PULLSPEC='REPLACE_ME_DEST_PULLSPEC'
cosign verify \
  --allow-insecure-registry \
  --key https://security.access.redhat.com/data/63405576.txt \
  --insecure-ignore-tlog \
  "${DEST_PULLSPEC}"
----

That output is how you see the signature on dest. The Validate Job grades ConfigMap `imageset-configuration` in `lightwell-repo` (the userinfo pull spec, with the placeholder gone), a completed Job `oc-mirror-learner`, `.sig` tags on the dest image, and the report key below. Verifying `registry.access.redhat.com` again is the 1.1 Check. Track 3 sets the application `FROM` to the dest pull spec you just verified.

== Key takeaways

* The signed base lives on the internal dest because you ran the mirror.
* The dest pull spec keeps the index digest from 1.1 and uses the Route host. The image path is `hi/openjdk`.
* The Job copies the image, then copies `.sig`, `.att`, and `.sbom` tags, because this Nexus dest stores signatures as tags.
* Lightwell libraries use the Maven proxy. Track 3 binds `FROM` to this dest pull spec.
