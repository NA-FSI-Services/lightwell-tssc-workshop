= 4.3 Build NetworkPolicy
:source-highlighter: rouge
:toc:
:toclevels: 2

NetworkPolicy `build-egress` on `lw-poc-build` is seeded *too open* (allow-all egress). You tighten it to deny-egress with DNS + internal registry + Nexus + in-cluster Gitea + the Kubernetes API. 4.4 clone / `oc start-build` need those last two. Do *not* allow public registry hosts or the worked-example `8.8.8.8`.

Do *not* copy this policy onto `lw-poc-staging` / `lw-poc-prod`. `app-operate` stays operate (Track 6).

== Learning objectives

By the end of this module, you will be able to:

* Replace allow-all egress with the documented allow-list from userinfo (including Gitea and kube API)
* Confirm the policy is live on `lw-poc-build` only
* Explain that `registry.redhat.io` is *not* on the scored hermetic list

== Worked example (not the Check)

Policy name `example-hermetic-egress`, namespace `example-build-ns`, extra CIDR `8.8.8.8/32`. Paste-identical copy fails.

[source,yaml]
----
# Worked example ONLY — wrong name, wrong namespace, public DNS.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: example-hermetic-egress
  namespace: example-build-ns
spec:
  podSelector: {}
  policyTypes: [Egress]
  egress:
    - to:
        - ipBlock:
            cidr: 8.8.8.8/32
----

Allow-list (from userinfo keys — do not invent CIDRs except the kube API ClusterIP you discover below):

* `openshift-dns` UDP (and TCP) port `5353`
* `openshift-image-registry` TCP `5000`
* `lightwell-repo` Nexus HTTP `8081` and Docker dest `5000`
* `gitea` TCP `3000` (in-cluster clone — not the Gitea Route)
* Kubernetes API: `default/kubernetes` ClusterIP TCP `443`, plus endpoint IPs TCP `6443` (hostNetwork masters; `namespaceSelector: default` does not match them)

Discover the API addresses (they differ per claim):

[source,bash,role=execute]
----
oc -n default get svc kubernetes -o jsonpath='clusterIP={.spec.clusterIP} port={.spec.ports[0].port}{"\n"}'
oc -n default get endpoints kubernetes -o jsonpath='{.subsets[*].addresses[*].ip}{" "}{.subsets[*].ports[*].port}{"\n"}'
----

== Your change: tighten `build-egress`

Replace the seed `egress: [ {} ]` with deny-by-default plus the destinations above (`namespaceSelector` on those namespaces, matching ports, plus `ipBlock` `/32` for the kube API ClusterIP and endpoint IPs). Do not add `registry.redhat.io` or a public CIDR. Do not rely on `namespaceSelector: openshift-ingress` for Routes — Route hostnames resolve to the ingress VIP, which that selector does not match. After 4.3, 4.4 must use in-cluster Gitea (`student_repo_internal_url`) and Nexus (`nexus_internal_url`), not HTTPS Routes.

[source,bash,role=execute]
----
oc -n lw-poc-build get networkpolicy build-egress -o yaml
# edit in place or oc apply a file you authored — not example-hermetic-egress.yaml
oc -n lw-poc-staging get networkpolicy app-operate
----

== Check: NP spec

Pass when:

* `build-egress` exists in `lw-poc-build`, is not allow-all egress, includes DNS + registry + Nexus
* Extra allows for Gitea and kube API are expected so 4.4 can run
* You did not copy it to `lw-poc-staging`
* `app-operate` on staging/prod is still the operate seed

After this tighten, a PipelineRun that still pulls `registry.redhat.io` / `registry.access.redhat.com` for *new* images will hang or fail. Task images pulled in 4.2 may already be cached. That is the lesson — not a reason to reopen egress.
