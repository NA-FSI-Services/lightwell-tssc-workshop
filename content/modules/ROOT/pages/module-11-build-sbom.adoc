= 4.4 Build and SBOM
:source-highlighter: rouge
:toc:
:toclevels: 2

OpenShift *BuildConfig* produces the app image in `lw-poc-build`. An SBOM is generated by the pipeline Task (Showroom `syft` may be missing: `syft_baked=false`). Image build is *not* Buildah. `oc tag` into staging is Track 6, not this Check. Keyless *verify* of the app image is Track 5.

== Learning objectives

By the end of this module, you will be able to:

* Run the pipeline / BuildConfig until an ImageStream tag exists
* Produce an SBOM file or OCI-attached SBOM
* Show the known-bad Dockerfile path still fails

== BuildConfig vs Buildah

Konflux “build” on hosted Konflux is often Buildah. This claim maps that control to Binary BuildConfig started from Tekton (`oc start-build --from-dir`). Do not add a Buildah task. Full term map: xref:appendix-konflux-mapping.adoc[Appendix: Konflux mapping].

== Delivery note

*Customers* get a signed, SBOMed image from CI. *You* prove the image landed and an SBOM exists. Admission and GitOps promotion are later tracks.

== Your change: successful pipeline in the build namespace

[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_build_namespace}')"
REPO_URL="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')"
echo "BUILD_NS=${BUILD_NS}"
oc -n "${BUILD_NS}" apply -f /tmp/spring-boot-lw-poc/.tekton/rbac.yaml
oc -n "${BUILD_NS}" apply -f /tmp/spring-boot-lw-poc/.tekton/pipeline.yaml
----

Edit `.tekton/pipelinerun.yaml`: replace `STUDENT_REPO_URL_PLACEHOLDER` with `student_repo_url`, replace `<lab-namespace>` with `lw-poc-build`, and fill Fulcio/Rekor/TUF from `demo-userinfo-rhtas` if the run includes the sign task (placeholders fail). Then:

[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_build_namespace}')"
oc -n "${BUILD_NS}" create -f /tmp/spring-boot-lw-poc/.tekton/pipelinerun.yaml
oc -n "${BUILD_NS}" get pipelinerun -w
----

Wait until `openshift-build` and `syft-sbom-rhtpa` succeed. ACS may fail or soft-skip; this Check is image + SBOM, not ACS (Track 7) and not cosign verify (Track 5).

== Check: image + SBOM; known-bad still fails

[source,bash,role=execute]
----
BUILD_NS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_build_namespace}')"
oc -n "${BUILD_NS}" get imagestream spring-boot-lw-poc
oc -n "${BUILD_NS}" get pipelinerun
# SBOM workspace / Task result — name may vary; confirm the syft task Succeeded
oc -n "${BUILD_NS}" get tr -l tekton.dev/pipelineTask=syft-sbom-rhtpa
----

Known-bad: start a build that uses `Dockerfile.known-bad` (or `oc start-build` with `-DdockerfilePath` if the BuildConfig allows). It must fail (public `FROM` / `curl` after 4.1–4.3). Do not leave the BuildConfig pointed at the known-bad file.

Honor system: Track 5 still opens.
