# Module 03 — Developer Hub Scaffolding (Java Golden Path)

### Brief Overview

This module establishes the canonical developer golden path by replacing the manually seeded Gitea repository from Module 2 with one generated by a Red Hat Developer Hub Software Template. It demonstrates how RHDH Software Templates encode enterprise standards (correct Maven profile, Lightwell-aware settings.xml, CI/CD pipeline wiring) directly into the scaffolding step, ensuring every new project starts supply-chain-secure by default. Learners discover the RHDH URL from a cluster ConfigMap, delete the seeded repo via the Gitea API, scaffold a new project via the `lightwell-java-service` template, and re-prove Maven stream resolution on the freshly scaffolded layout.

### Audience and Time

- **Personas:** Java developers, DevSecOps engineers, platform engineers
- **Prerequisites for this module:** Module 2 complete; RHDH accessible; Gitea accessible; oc CLI available; Maven installed
- **Estimated duration:** 25 min

### Learning Objectives

- Scaffold a Java application repository from a Red Hat Developer Hub Software Template using the lightwell-java-service golden path
- Verify that the scaffolded repository resolves both Lightwell Validated and Remediated Maven coordinates correctly

### Lab Structure

| Section | Title | Duration |
|---------|-------|----------|
| 1 | Discover RHDH and Gitea URLs from ConfigMaps | 4 min |
| 2 | Delete the seeded app repo via Gitea API | 3 min |
| 3 | Scaffold from Developer Hub using lightwell-java-service template | 12 min |
| 4 | Clone and verify Maven streams on the scaffolded repo | 6 min |

### Detailed Steps

1. Run `oc -n rhdh get configmap demo-userinfo-rhdh -o yaml` to extract the RHDH console URL and Gitea base URL for the learner's user.
2. Note the Gitea organization/username and the RHDH URL from the ConfigMap output.
3. **Delete seeded repo:** Use the Gitea API to delete the seeded `spring-boot-lw-poc` repository — run `curl -sk -X DELETE -H "Authorization: basic <b64creds>" https://<gitea-url>/api/v1/repos/<username>/spring-boot-lw-poc`.
4. Verify the repo is deleted by visiting the Gitea UI or running a GET request against the same API path — expect a 404 response.
5. **Open RHDH:** Navigate to the RHDH console URL in the browser. Log in with the workshop credentials.
6. Go to **Create → Software Templates** and locate the `lightwell-java-service` template.
7. Fill in the template form: application name (`spring-boot-lw-poc`), Gitea organization, owner username, and confirm the Lightwell Maven profile is pre-selected.
8. Submit the template. Wait for RHDH to create the Gitea repository, scaffold the project layout, and register the component in the catalog.
9. Once the scaffolding task completes (shown as "Done" in the RHDH task pane), navigate to the new component in the RHDH catalog and confirm it appears.
10. **Clone the scaffolded repo:** Run `git clone https://<gitea-url>/<username>/spring-boot-lw-poc.git`.
11. Inspect the scaffolded `settings.xml` to confirm it includes the `lightwell-validated` and `lightwell-remediated` profiles generated by the template.
12. Run `mvn clean verify -s settings.xml -Plightwell-validated` to prove Validated resolution from the scaffolded project.
13. Run `mvn clean verify -Plightwell-remediated,lightwell-remediated-pins` to prove Remediated resolution.
14. **Verification:** Both builds return `BUILD SUCCESS` — the scaffolded project resolves from Lightwell Nexus repos without manual settings.xml editing.

### Key Takeaways

- RHDH Software Templates are the organizational mechanism for encoding supply-chain security standards — every Java project scaffolded via `lightwell-java-service` automatically gets Lightwell-aware Maven profiles.
- Deleting and re-creating the repo via the golden path mirrors the real enterprise onboarding flow, replacing ad-hoc project creation with governed scaffolding.
- The Gitea API DELETE approach is intentional — it shows learners that the seeded repo is not the real starting point; the template-driven repo is.
- After scaffolding, the Maven proof steps are identical to Module 2, confirming that template-generated projects work the same as manually configured ones.
- RHDH catalog registration is a side effect of scaffolding — the component appears in the software catalog without manual entry.

### Infrastructure Notes

- RHDH must be running with the `lightwell-java-service` Software Template pre-loaded and accessible to workshop users.
- Gitea must accept API DELETE requests with basic auth credentials from the learner's user.
- The Gitea seeded repo (`spring-boot-lw-poc`) must exist at module start so the delete step is meaningful.
- RHDH → Gitea integration must be configured to allow RHDH to create repos in the learner's Gitea organization.
