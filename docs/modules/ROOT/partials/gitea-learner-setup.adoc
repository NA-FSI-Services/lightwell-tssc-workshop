== Exercise: Create your Gitea organization and seed lab repositories

Lab automation starts **Gitea** and normally creates your **user account** (`student_username` / `student_password` in ConfigMap `demo-userinfo-gitea`).
If sign-in fails, run the ensure-user helper below (uses Secret `gitea-admin`).
You create the **Organization** and **repositories** you will use for the rest of the workshop, then seed them from operator-prepared **templates** (isolated monorepo content — never clone GitHub).

=== Conventions

[cols="1,2",options="header"]
|===
|Item |Value

|Your organization
|`lw-@@LW_USER@@` (`student_gitea_org`)

|Application repo
|`spring-boot-lw-poc` → `student_repo_url`

|GitOps repo
|`gitops-spring-boot-lw-poc` → `student_gitops_repo_url`

|Template org (read-only)
|`workshop-templates`
|===

=== A. Discover Gitea, ensure your user, and create the organization

Lab install creates your Gitea account when Job `gitea-student-repo-seed` runs (dev-cluster default: *pass:q[<span class="lw-student-user">student</span>]*). Confirm the URL and credentials from the ConfigMap, then ensure the account exists before signing in.

Discover the Gitea URL and your username (do **not** paste a hardcoded hostname):

[source,bash,role=execute]
----
oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='gitea_url={.data.gitea_url}{"\n"}student_username={.data.student_username}{"\n"}'
----

Ensure your user can sign in (no-op if the seed Job already created you; otherwise creates/updates via workshop admin Secret `gitea-admin`):

[source,bash,role=execute]
----
export STUDENT_USER='@@LW_USER@@'
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"

oc -n gitea get configmap gitea-student-repo-seed \
  -o jsonpath='{.data.learner-ensure-gitea-user\.sh}' > /tmp/learner-ensure-gitea-user.sh
chmod +x /tmp/learner-ensure-gitea-user.sh
/tmp/learner-ensure-gitea-user.sh
----

The script prints **Open:** `<gitea_url>`. Open that URL in your browser and sign in as *pass:q[<span class="lw-student-user">student</span>]* with `student_password` from `demo-userinfo-gitea` (same password the script used).

. Click **+** → **New Organization**
. Set **Organization Name** exactly to *`lw-@@LW_USER@@`* (must match `student_gitea_org`)
. Visibility: **Public** → **Create Organization**

=== C. Seed from workshop templates

Operator Job `gitea-student-repo-seed` already published prepared trees under `workshop-templates/` (path-isolated from the monorepo). Copy that content into **your** repos:

[source,bash,role=execute]
----
export STUDENT_USER='@@LW_USER@@'
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"

oc -n gitea get configmap gitea-student-repo-seed \
  -o jsonpath='{.data.learner-seed-from-templates\.sh}' > /tmp/learner-seed.sh
chmod +x /tmp/learner-seed.sh
/tmp/learner-seed.sh
----

The script also adds workshop user `gitea-admin` to your org’s **Owners** team so Module 3 RHDH `publish:gitea` can create repositories under *`lw-@@LW_USER@@`*.

Confirm:

[source,bash,role=execute]
----
oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_repo_url}{"\n"}{.data.template_app_repo_url}{"\n"}'
curl -sk -o /dev/null -w "%{http_code}\n" \
  "$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')"
----

Expect HTTP `200` on the app remote (anonymous clone works for public repos). Open `lw-@@LW_USER@@/spring-boot-lw-poc` in Gitea and confirm `pom.xml` is at the repository root.
