Modules 7–8 wired PyPI Validated / Remediated, the FastAPI tree in *your* Gitea org, and SPDX / CycloneDX into RHTPA. This module closes the Python trusted supply-chain loop—parallel to xref:module-06-pipeline.adoc[Module 6] for Java: Tekton policy gates that *fail* without the Remediated marker pin and *pass* after it is restored, *Red Hat Advanced Cluster Security (RHACS)* image policy, *keyless* signing with *Red Hat Trusted Artifact Signer (RHTAS)*, and GitOps promotion with Argo CD.

Lightwell and *Advanced Cluster Security (ACS)* stay complementary: Lightwell remediates (or, in this workshop, seeds a demonstrable `.rhlw-*` marker); ACS and the Python dep-gate / image-check Tasks *enforce* policy before promotion.

== Learning objectives

By the end of this module, you will be able to:

* Run the Python policy Pipeline and explain the fail-then-pass `.rhlw-*` narrative on `requirements.txt`
* Relate RHACS `roxctl image check` to BUILD policy enforcement on the FastAPI image path
* Sign and verify an image with cosign keyless (Fulcio / Rekor / *The Update Framework (TUF)*)
* Promote a signed digest via your Python GitOps remote and confirm Argo CD sync

real `roxctl` evaluation:

[source,bash,role=execute]

If the Job is missing or the secret has no token (rare on a healthy claim), use the same cluster-admin
fallback documented in xref:module-06-pipeline.adoc[Module 6 Exercise 2] (`./scripts/dev-cluster-rhacs-ci-token.sh` or Central UI → **Platform Configuration → Integrations → API Tokens**).

With the token present, re-run the PipelineRun and confirm `acs-image-check` `check-status` is
`passed` or `failed` (not `skipped`). Workshop default `fail-on-skipped=false` still soft-skips
if the secret is empty so the dep-gate narrative can continue—treat a skip as a provisioning gap,
not the happy path.

[TIP]
====
On a *fresh* claim, RHACS Scanner V4 may still be loading its vulnerability store when you create the
pass PipelineRun. `acs-image-check` can then fail with `matcher is not initialized` / `initial load
… in progress` even though the CI token is present and `lightwell-python-dep-gate` already passed.
That is a timing gap, not a bad pin.

Wait a few minutes (or until Central / Scanner pods look Ready), then re-create the pass PipelineRun.
Treat `gate-status=passed` as the Exercise 2 teaching beat; expect a clean ACS result on the
Exercise 3 FastAPI image once the matcher is ready.

. After a successful `cosign-sign-keyless` task, verify the signature from Showroom (or a workstation with cosign). Stock Showroom terminals often ship *without* `cosign` on `PATH`, and `/home/lab-user` is often **not writable** (cosign needs `~/.sigstore` and `~/.docker`). Install under `/tmp` and set `HOME=/tmp/lab-home`:
+
[source,bash,role=execute]
----
# Install cosign once per terminal session (Showroom-friendly; uses /tmp)
mkdir -p /tmp/bin /tmp/lab-home
curl -sSfL -o /tmp/bin/cosign \
  https://github.com/sigstore/cosign/releases/download/v2.4.3/cosign-linux-amd64
chmod +x /tmp/bin/cosign
export PATH="/tmp/bin:$PATH"
# Showroom /home/lab-user is often not writable — cosign needs ~/.sigstore and ~/.docker
export HOME=/tmp/lab-home
cosign version
----
+
Initialize TUF, then verify with the pipeline SA identity confirmed on claim:
+
[source,bash,role=execute]
----
# Reuse writable HOME from the install step (or set again if you opened a new shell)
mkdir -p /tmp/lab-home
export HOME=/tmp/lab-home
export PATH="/tmp/bin:$PATH"

export IMAGE_URL="image-registry.openshift-image-registry.svc:5000/${LAB_NS}/fastapi-lw-poc:latest"
export TUF="https://tuf-trusted-artifact-signer.${DOMAIN}"
export REKOR="https://rekor-server-trusted-artifact-signer.${DOMAIN}"
# If verifying from outside the cluster, use the exposed registry route / mirrored digest instead.

cosign initialize --mirror="${TUF}" --root="${TUF}/root.json"

# Registry auth for in-cluster verify (Showroom SA / pipeline token):
cosign login -u unused -p "$(cat /var/run/secrets/kubernetes.io/serviceaccount/token)" \
  image-registry.openshift-image-registry.svc:5000

cosign verify \
  --rekor-url="${REKOR}" \
  --certificate-identity-regexp="^https://kubernetes.io/namespaces/${LAB_NS}/serviceaccounts/pipeline$" \
  --certificate-oidc-issuer="https://kubernetes.default.svc" \
  --allow-http-registry --allow-insecure-registry \
  "${IMAGE_URL}"
----
+
Expect certificate identity `https://kubernetes.io/namespaces/<lab-ns>/serviceaccounts/pipeline` with issuer `https://kubernetes.default.svc` (same RHTAS pattern as Module 6). If verify fails on another claim, capture the certificate identity from Rekor and adjust—do not invent alternate issuers without claim evidence.
