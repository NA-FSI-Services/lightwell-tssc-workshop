= Module 5: Pipeline signing, policy, and GitOps promotion
:source-highlighter: rouge
:toc:
:toclevels: 2

Modules 2–4 wired Maven remotes, exact-version `.rhlw-*` pins, and CycloneDX into RHTPA. This module closes the trusted supply-chain loop: Tekton policy gates that *fail* on non-remediated pins and *pass* after remediation, *Red Hat Advanced Cluster Security (RHACS)* image policy, *keyless* signing with *Red Hat Trusted Artifact Signer (RHTAS)*, and GitOps promotion with Argo CD.

Lightwell and *Advanced Cluster Security (ACS)* are complementary: Lightwell remediates application dependencies; ACS (and this workshop’s dep-gate / image-check Tasks) *enforce* that builds and images meet policy before promotion. OSV and VEX metadata help *continuous integration (CI)* scanners recognize remediated pins so gates and third-party scanners stay aligned.

== Learning objectives

By the end of this module, you will be able to:

* Run the workshop policy Pipeline and explain the fail-then-pass `.rhlw-*` narrative
* Relate RHACS `roxctl image check` to BUILD policy enforcement (ACS + Lightwell coexistence)
* Sign and verify an image with cosign keyless (Fulcio / Rekor / *The Update Framework (TUF)*)
* Confirm Argo CD syncs the App-of-Apps / sample app after a successful path

=== RHACS image check

GitOps Job `rhacs-ci-token-mint` mints a Central **Continuous Integration** API token into Secret
`rhacs-ci-secrets` after Central is Ready (never commit the token). Confirm before expecting a
real `roxctl` evaluation:

[source,bash,role=execute]
----
oc -n stackrox get job rhacs-ci-token-mint
# Non-zero length means the token key is present (do not print the token)
oc -n stackrox get secret rhacs-ci-secrets -o jsonpath='{.data.rox-api-token}' | wc -c
----

If the Job is missing or the secret has no token (rare on a healthy claim), use a cluster-admin
fallback: `./scripts/dev-cluster-rhacs-ci-token.sh`, or create the token in Central UI →
**Platform Configuration → Integrations → API Tokens** (role **Continuous Integration**) and
patch the Secret:

[source,bash]
----
oc -n stackrox create secret generic rhacs-ci-secrets \
  --from-literal=rox-api-endpoint='central-stackrox.apps.<domain>:443' \
  --from-literal=rox-api-token='<TOKEN>' \
  --dry-run=client -o yaml | oc apply -f -
----

Import the Fixable Critical BUILD policy from ConfigMap `rhacs-lightwell-central-policy` (Central UI → Policy Management) when teaching scanner-backed fails/passes on real images.

With the token present, re-run the PipelineRun and confirm `acs-image-check` `check-status` is
`passed` or `failed` (not `skipped`). Workshop default `fail-on-skipped=false` still soft-skips
if the secret is empty so the dep-gate narrative can continue—treat a skip as a provisioning gap,
not the happy path.

[TIP]
====
On a *fresh* claim, RHACS Scanner V4 may still be loading its vulnerability store when you create the
pass PipelineRun. `acs-image-check` can then fail with `matcher is not initialized` / `initial load
… in progress` even though the CI token is present and `lightwell-dep-gate` already passed.
That is a timing gap, not a bad pin.

Wait a few minutes (or until Central / Scanner pods look Ready), then re-create the pass PipelineRun.
Treat `gate-status=passed` as the Exercise 2 teaching beat; expect a clean ACS result on the
Exercise 3 app image once the matcher is ready.
====

== Exercise 3: Keyless sign and verify (RHTAS)

RHTAS provides Fulcio, Rekor, and TUF for *keyless* cosign—no long-lived private keys in the workshop.

This exercise uses your **Gitea** student repository (path-isolated app + `.tekton/` overlay). Do **not** clone GitHub for the app remote. Image build uses an OpenShift **BuildConfig** (Dockerfile multi-stage; Maven Central inside the image build). Tekton runs dep-gate → build → ACS → SBOM → cosign. The image stays in your **learner lab namespace** — Exercise 4 promotes it into your product namespace via the Gitea **gitops** remote.

IMPORTANT: Needs OpenShift Pipelines from chart `pipelines` (`git-clone` and Tekton CRDs), RHACS Tasks in `stackrox`, Job `rhacs-ci-token-mint` for a real `acs-image-check`, and pull access to `registry.redhat.io/rhtas/cosign-rhel9` for the sign step. # Registry auth for in-cluster verify (pipeline SA token):

== Exercise 4: GitOps promotion (Argo CD)

Promotion means: tag the signed lab image into your **product** namespace, commit the image **digest** and `replicas: 1` to your **Gitea gitops** repo, let Argo CD sync, and confirm the Route is Healthy. You do not `oc apply` long-lived Deployment YAML by hand.

[NOTE]
====
You have **two** Gitea remotes (never GitHub):

* `student_repo_url` — application source + `.tekton/` (Exercises 1–3)
* `student_gitops_repo_url` — thin Helm chart (no `./app`); Argo CD ApplicationSet syncs this into `student_promote_namespace` (`lw-poc-<username>`)

The workshop monorepo Application for `spring-boot-lw-poc` stays **disabled**. Runtime desired state is your Gitea gitops repo.
====

. Discover promote coordinates from userinfo:
+
[source,bash,role=execute]
----
export LAB_NS="${LAB_NS:-student-lab}"
export PROMOTE_NS="$(oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_promote_namespace}')"
export GITOPS_REPO_URL="$(oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_gitops_repo_url}')"
export ARGO_APP="$(oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_argocd_app}')"
export STUDENT_USER="$(oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='{.data.student_username}')"
export STUDENT_PASS="$(oc -n gitea get configmap demo-userinfo-gitea \

echo "ARGO_APP=${ARGO_APP}"

. Confirm the ApplicationSet child Application exists and is Synced (chart at `replicas: 0`, empty digest → Healthy without ImagePullBackOff):
+
[source,bash,role=execute]
----

----

. Tag the signed lab image into the product ImageStream (R1):
+
[source,bash,role=execute]
----

# Digest for values.yaml (keep the sha256: prefix)
export IMAGE_DIGEST="$(oc -n "${PROMOTE_NS}" get imagestreamtag spring-boot-lw-poc:latest \
  -o jsonpath='{.image.metadata.name}')"
echo "IMAGE_DIGEST=${IMAGE_DIGEST}"
test -n "${IMAGE_DIGEST}" && [[ "${IMAGE_DIGEST}" == sha256:* ]]
----

. Clone your **gitops** Gitea repo, pin digest + scale up, commit, and push:
+
[source,bash,role=execute]
----
rm -rf /tmp/gitops-spring-boot-lw-poc
git clone "${GITOPS_REPO_URL}" /tmp/gitops-spring-boot-lw-poc
cd /tmp/gitops-spring-boot-lw-poc

# Patch values.yaml: set image.digest and replicas: 1
python3 - <<PY
from pathlib import Path
import os, re
p = Path("values.yaml")
text = p.read_text()
digest = os.environ["IMAGE_DIGEST"]
text = re.sub(r'(?m)^(\s*digest:\s*).*$', r'\1"' + digest + '"', text, count=1)
text = re.sub(r'(?m)^replicas:\s*\d+\s*$', "replicas: 1", text, count=1)
p.write_text(text)
print(p.read_text().split("image:")[1][:400])
PY

git config user.email "${STUDENT_USER}@workshop.local"
git config user.name "${STUDENT_USER}"
git add values.yaml
git commit -m "Promote signed image digest and scale to 1 replica"
# Prefer credential helper / URL from userinfo — do not commit passwords
git push "https://${STUDENT_USER}:${STUDENT_PASS}@${GITOPS_REPO_URL#https://}" HEAD:main
----

. Wait for Argo CD auto-sync (or refresh), then verify Healthy Deployment + Route:
+
[source,bash,role=execute]
----
# Force Argo to re-read the Gitea gitops tip if status looks stale after push
oc -n openshift-gitops annotate applications.argoproj.io/${ARGO_APP} \
  argocd.argoproj.io/refresh=hard --overwrite

oc -n openshift-gitops wait --for=jsonpath='{.status.sync.status}'=Synced \
  "applications.argoproj.io/${ARGO_APP}" --timeout=180s || true
oc -n openshift-gitops get applications.argoproj.io "${ARGO_APP}" \
  -o custom-columns=NAME:.metadata.name,SYNC:.status.sync.status,HEALTH:.status.health.status

# Expect replicas=1 and image …@sha256:… after the promote commit syncs
oc -n "${PROMOTE_NS}" get deploy,pods,route
ROUTE_HOST="$(oc -n "${PROMOTE_NS}" get route spring-boot-lw-poc \
  -o jsonpath='{.spec.host}')"
curl -sk "https://${ROUTE_HOST}/api/healthz" || curl -sk "https://${ROUTE_HOST}/api/greeting"

If the Application stays `Unknown` / clone errors *right after seed*, wait for the Gitea gitops
repo to finish seeding, then hard-refresh the same way.
