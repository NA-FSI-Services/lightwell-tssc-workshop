= Module 5: Pipeline signing, policy, and GitOps promotion
:source-highlighter: rouge
:toc:
:toclevels: 2

Modules 2–4 wired Maven remotes, exact-version `.rhlw-*` pins, and CycloneDX into RHTPA. This module closes the trusted supply-chain loop: Tekton policy gates that *fail* on non-remediated pins and *pass* after remediation, RHACS image policy, *keyless* signing with Red Hat Trusted Artifact Signer (RHTAS), and GitOps promotion with Argo CD.

Lightwell and ACS are complementary: Lightwell remediates application dependencies; ACS (and this workshop’s dep-gate / image-check Tasks) *enforce* that builds and images meet policy before promotion. OSV and VEX metadata help CI scanners recognize remediated pins so gates and third-party scanners stay aligned.

== Learning objectives

By the end of this module, you will be able to:

* Run the workshop policy Pipeline and explain the fail-then-pass `.rhlw-*` narrative
* Relate RHACS `roxctl image check` to BUILD policy enforcement (ACS + Lightwell coexistence)
* Sign and verify an image with cosign keyless (Fulcio / Rekor / TUF)
* Confirm Argo CD syncs the App-of-Apps / sample app after a successful path

== Exercise 1: Failure path (non-remediated pin)

Default `spring-boot-lw-poc` properties pin `commons-lang3` at `3.14.0` (*no* `.rhlw-*`). With `dep-gate-mode=require-remediated`, Task `lightwell-dep-gate` must fail.

. Confirm Tasks and Pipeline exist:
+
[source,bash,role=execute]
----
oc -n stackrox get tasks lightwell-dep-gate acs-image-check syft-sbom-rhtpa
oc -n stackrox get pipeline lightwell-build-policy-gate
----

. Extract the sample fail PipelineRun from the lab ConfigMap and create it:
+
[source,bash,role=execute]
----
oc -n stackrox get configmap rhacs-lightwell-policy-lab \
  -o jsonpath='{.data.fail_pipelinerun\.yaml}' > /tmp/lightwell-policy-fail.yaml

# Confirm repo-url matches your student Gitea remote (pom-path=pom.xml at repo root)
grep -E 'pom-path|dep-gate|repo-url' /tmp/lightwell-policy-fail.yaml
oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}{"\n"}'

oc -n stackrox create -f /tmp/lightwell-policy-fail.yaml
----

. Watch until `lightwell-dep-gate` fails:
+
[source,bash,role=execute]
----
tkn -n stackrox pipelinerun list
# Or:
oc -n stackrox get pipelineruns --sort-by=.metadata.creationTimestamp | tail -5

PR=$(oc -n stackrox get pipelinerun -o name --sort-by=.metadata.creationTimestamp | tail -1)
tkn -n stackrox pipelinerun logs "$(basename "$PR")" -f
----

. Expected log themes:
* `FAIL: non-remediated default pin for commons-lang3`
* Required version mentions `3.14.0.rhlw-00001`
* Result `gate-status=failed`

[TIP]
====
If `tkn` is unavailable, use `oc logs` on the TaskRun pods for `lightwell-dep-gate`.
====

== Exercise 2: Success path (remediated `.rhlw-*` pin)

. Clone **your** student repository, set the *default* properties pin (the gate reads `<properties>`, not only the profile block), commit, and push:
+
[source,bash,role=execute]
----
: "${STUDENT_REPO_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')}"
: "${STUDENT_USER:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_username}')}"
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"

git clone "https://${STUDENT_USER}:${STUDENT_PASS}@${STUDENT_REPO_URL#https://}" /tmp/student-lw-poc
cd /tmp/student-lw-poc
# Edit pom.xml — default <commons.lang3.version> must become 3.14.0.rhlw-00001
----
+
[source,xml]
----
<properties>
  <commons.lang3.version>3.14.0.rhlw-00001</commons.lang3.version>
</properties>
----
+
[source,bash,role=execute]
----
git add pom.xml
git commit -m "Pin commons-lang3 to remediated .rhlw-00001"
git push origin main
----

. Create a success PipelineRun against **your** student remote (keep `dep-gate-mode=require-remediated`):
+
[source,bash,role=execute]
----
: "${STUDENT_REPO_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')}"
: "${STUDENT_REPO_REV:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_revision}')}"
: "${STUDENT_POM_PATH:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_pom_path}')}"

oc -n stackrox create -f - <<EOF
apiVersion: tekton.dev/v1
kind: PipelineRun
metadata:
  generateName: lightwell-policy-pass-
  namespace: stackrox
spec:
  pipelineRef:
    name: lightwell-build-policy-gate
  params:
    - name: repo-url
      value: ${STUDENT_REPO_URL}
    - name: revision
      value: ${STUDENT_REPO_REV}
    - name: image
      value: quay.io/centos/centos:stream9
    - name: dep-gate-mode
      value: require-remediated
    - name: pom-path
      value: ${STUDENT_POM_PATH}
    - name: rhtpa-url
      value: ""
  workspaces:
    - name: source
      volumeClaimTemplate:
        spec:
          accessModes: ["ReadWriteOnce"]
          resources:
            requests:
              storage: 1Gi
    - name: sbom
      emptyDir: {}
EOF
----
+
[IMPORTANT]
====
Push the remediated pin to **your** Gitea repository before creating the pass PipelineRun. Do not point `repo-url` at the workshop GitOps monorepo.
====

. Verify results:
+
[source,bash,role=execute]
----
PR=$(oc -n stackrox get pipelinerun -l !tekton.dev/pipeline=  -o name --sort-by=.metadata.creationTimestamp 2>/dev/null | tail -1)
# Simpler: pick the latest pass run by name prefix
oc -n stackrox get pipelinerun | egrep 'lightwell-policy|NAME'

# Inspect Task results when complete:
oc -n stackrox get taskrun -l tekton.dev/pipelineTask=lightwell-dep-gate \
  -o jsonpath='{range .items[-1:]}{.metadata.name}{" gate-status="}{.status.results[?(@.name=="gate-status")].value}{"\n"}{end}'
----

. Expected: `gate-status=passed`, then `acs-image-check` and `syft-sbom-rhtpa` continue.

=== RHACS image check

Populate CI secrets when you want a real `roxctl` evaluation (never commit the token).

On a **dev claim** (cluster-admin + Central Ready), mint a Continuous Integration token and patch the Secret:

[source,bash]
----
./scripts/dev-cluster-rhacs-ci-token.sh
----

Or create the token in Central UI → **Platform Configuration → Integrations → API Tokens** (role **Continuous Integration**), then:

[source,bash]
----
oc -n stackrox create secret generic rhacs-ci-secrets \
  --from-literal=rox-api-endpoint='central-stackrox.apps.<domain>:443' \
  --from-literal=rox-api-token='<TOKEN>' \
  --dry-run=client -o yaml | oc apply -f -
----

Import the Fixable Critical BUILD policy from ConfigMap `rhacs-lightwell-central-policy` (Central UI → Policy Management) when teaching scanner-backed fails/passes on real images.

Without a `rox-api-token`, `acs-image-check` *skips* (workshop default `fail-on-skipped=false`)—still note the Task in the pipeline graph. After the token is present, re-run the PipelineRun and confirm `check-status` is `passed` or `failed` (not `skipped`).

== Exercise 3: Keyless sign and verify (RHTAS)

RHTAS provides Fulcio, Rekor, and TUF for *keyless* cosign—no long-lived private keys in the workshop.

IMPORTANT: Full scaffolded build+sign needs OpenShift Pipelines Tasks, RHACS Tasks in `stackrox`, registry pull for `registry.redhat.io/rhtas/cosign-rhel9`, and Maven/LWN credentials for the pipeline SA. If those are not ready on your claim, complete the orientation steps below and treat end-to-end sign as instructor-led.

. Inspect the Securesign instance and note Fulcio/Rekor/TUF Routes (also in userinfo ConfigMap `demo-userinfo-rhtas`):
+
[source,bash,role=execute]
----
oc -n trusted-artifact-signer get securesign
oc -n trusted-artifact-signer get routes
oc -n trusted-artifact-signer get configmap demo-userinfo-rhtas -o yaml
----

. From an RHDH-scaffolded `lightwell-java-service` (skeleton under the RHDH chart):
+
[source,bash,role=execute]
----
# In the scaffolded repo namespace:
oc apply -f .tekton/rbac.yaml
oc apply -f .tekton/pipeline.yaml
# Edit pipelinerun: image-url + cosign-fulcio-url / cosign-rekor-url from Routes above
oc create -f .tekton/pipelinerun.yaml
----
+
Use `maven-profile` = `lightwell-remediated-pins` (skeleton default) so `lightwell-dep-gate` sees `.rhlw-*` in POM properties. Profile-only `-P` without updating properties will fail the gate.

. After a successful `cosign-sign-keyless` task, verify the signature (from a workstation or debug pod with cosign + TUF root):
+
[source,bash,role=execute]
----
# Pattern — substitute image and Fulcio/Rekor/TUF endpoints from your cluster
# cosign verify \
#   --fulcio-url="https://fulcio-server-trusted-artifact-signer.apps.<domain>" \
#   --rekor-url="https://rekor-server-trusted-artifact-signer.apps.<domain>" \
#   "${IMAGE_URL}"
----

. Confirm the log line `Signed … (keyless / RHTAS)` on the PipelineRun.

[TIP]
====

== Exercise 4: GitOps promotion (Argo CD)

Promotion in this workshop means: commit desired state in Git, let Argo CD sync, and confirm OpenShift resources are Healthy. You do not `oc apply` long-lived app config by hand.

[NOTE]
====
Your **student** Gitea repository holds application source for pipeline labs (Exercises 1–3).
Argo CD App-of-Apps syncs *platform / chart desired state* from the catalog GitOps path — that is separate from the learner remotes you clone and push to.
====


. List Applications managed by the root App-of-Apps:
+
[source,bash,role=execute]
----
oc -n openshift-gitops get applications.argoproj.io
# Names vary by release; look for root-app children such as *-spring-boot-lw-poc, *-rhacs, *-rhtas
----

. Check sync/health for the sample app Application:
+
[source,bash,role=execute]
----
oc -n openshift-gitops get applications.argoproj.io \
  -o custom-columns=NAME:.metadata.name,SYNC:.status.sync.status,HEALTH:.status.health.status \
  | egrep -i 'spring-boot|NAME|lightwell|root' || true
----

. In the Argo CD UI, open the root application and confirm child apps (including `spring-boot-lw-poc` when enabled) are *Synced* / *Healthy*.

. Promotion beat (field narrative):
* Merge / push image tag or chart values change to Git (for example bump the PoC image digest after a signed build)
* Argo CD detects the commit (or you click *Refresh* / *Sync*)
* Deployment rolls out the signed image; earlier gates ensure only remediated pins reached the registry

== End-to-end checklist

[cols="1,2",options="header"]
|===
|Step |Pass criteria

|Dep gate fail
|Default `3.14.0` yields `gate-status=failed`

|Dep gate pass
|Default / properties `3.14.0.rhlw-00001` yields `gate-status=passed`

|RHACS
|`acs-image-check` passed or intentionally skipped with documented secrets gap

|SBOM
|CycloneDX written; uploaded or manual RHTPA UI

|Sign / verify

|===

**Key takeaways**
