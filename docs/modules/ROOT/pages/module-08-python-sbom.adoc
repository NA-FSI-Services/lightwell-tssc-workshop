This module continues the **Python track** after xref:module-07-pypi.adoc[Module 7]. You prove a *Remediated* PyPI pin (same *Validated* / *Remediated* tier names as Java), contrast Python *Software Package Data Exchange (SPDX)* inventory with the Java *CycloneDX* path from xref:module-05-sbom.adoc[Module 5], then ingest an application SBOM into *Red Hat Trusted Profile Analyzer (RHTPA)*.

== Learning objectives

By the end of this module, you will be able to:

* Confirm workshop Nexus exposes PyPI *Remediated* (`pypi_remediated_enabled=true`)
* Install `lw-workshop-pypi==1.0.0+rhlw.00001`, add it to `requirements.txt`, commit, and push to your Gitea FastAPI repo
* Contrast Maven / CycloneDX packaging metadata with Python / SPDX (and inspect wheel `*.dist-info`)
* Generate SPDX and CycloneDX inventories from the FastAPI tree with `syft`
* Ingest into RHTPA (CycloneDX is the reliable workshop path; try SPDX when supported) and browse the result

== Exercise 2 — Pin Remediated marker

=== A. Clone your FastAPI repo and install the marker

----

rm -rf /tmp/fastapi-lw-poc
# Authenticated clone so later push works without rewriting remotes
git clone "https://${STUDENT_USER}:${STUDENT_PASS}@${STUDENT_PYTHON_REPO_URL#https://}" /tmp/fastapi-lw-poc
cd /tmp/fastapi-lw-poc

ls -la requirements.txt pip.conf pip-remediated.conf
----

Prefer the cluster ConfigMap for the Remediated index (correct host for this claim):

[source,bash,role=execute]
----
oc -n lightwell-repo extract configmap/lightwell-pip-settings \
  --keys=pip-remediated.conf --to=/tmp/fastapi-lw-poc --confirm

python3 -m venv /tmp/fastapi-venv-m8
source /tmp/fastapi-venv-m8/bin/activate

PIP_CONFIG_FILE=/tmp/fastapi-lw-poc/pip-remediated.conf \
  python3 -m pip install 'lw-workshop-pypi==1.0.0+rhlw.00001' \
  > /tmp/pip-remediated-marker.log 2>&1

grep -E 'lw-workshop-pypi|lightwell-python-remediated|Successfully installed|ERROR' \
  /tmp/pip-remediated-marker.log | tail -40

python3 -m pip show lw-workshop-pypi | grep -E '^(Name|Version|Location):'
----

Expected: version `1.0.0+rhlw.00001` from Nexus `lightwell-python-remediated` (seeded workshop marker — PEP 440 local `+rhlw.*` so pip accepts it; not a live product backport of a framework package).

== Exercise 3 — SPDX vs CycloneDX and wheel `dist-info`

Lightwell-distributed *Maven* packages typically carry *CycloneDX* SBOMs (and VEX). *Python* wheels commonly carry *SPDX* under packaging metadata. This workshop still uses CycloneDX for the reliable RHTPA ingest path (same API as Module 5).

[cols="1,2,2",options="header"]
|===
|Concern |Java (Modules 4–5) |Python (this module)

|*Remediated pin*
|`.rhlw-*` on Maven GAV (e.g. `commons-lang3`)
|PEP 440 local `+rhlw.*` on pip (`lw-workshop-pypi==1.0.0+rhlw.00001`)

|*Package metadata SBOM*
|CycloneDX (+ VEX) with the artifact
|SPDX under `*.dist-info/sboms/` on live LWN wheels (when published)

|*Application inventory in lab*
|`syft` → CycloneDX → RHTPA
|`syft` → SPDX (Python-native) *and* CycloneDX (RHTPA path)
|===

image::module-08-spdx-vs-cyclonedx.png[SPDX vs CycloneDX packaging contrast,width=700]

=== Inspect the installed marker wheel layout

With the venv still active (or reactivate it):

[source,bash,role=execute]
----
source /tmp/fastapi-venv-m8/bin/activate

LOC="$(python3 -m pip show lw-workshop-pypi | awk -F': ' '/^Location:/{print $2; exit}')"
echo "Location=${LOC}"

# Seeded marker dist-info (METADATA / WHEEL / RECORD)

# Honest check: embedded sboms/ is a live LWN packaging pattern — not in this seed marker
ls -la "${LOC}"/lw_workshop_pypi-*.dist-info/sboms 2>/dev/null \
  || echo "No *.dist-info/sboms/ on workshop marker (expected for seed); live LWN wheels may ship SPDX here."

----

[TIP]
====
*Instructor:* Do not imply the workshop marker ships production SPDX under `sboms/`. The teaching beat is (1) where live LWN Python metadata lives, (2) that learners still generate an *application* SBOM with `syft` for RHTPA—parallel to Module 5 scanning `target/`, not only browsing Nexus component SBOMs.
====

== Exercise 4 — Generate SPDX and CycloneDX with `syft`

Work from the FastAPI clone:

[source,bash,role=execute]
----
: "${STUDENT_PYTHON_REPO_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_python_repo_url}')}"

if [[ ! -d /tmp/fastapi-lw-poc/.git ]]; then
  rm -rf /tmp/fastapi-lw-poc
  git clone "${STUDENT_PYTHON_REPO_URL}" /tmp/fastapi-lw-poc
fi
cd /tmp/fastapi-lw-poc
----

Install `syft` under `/tmp` if needed (same pattern as Module 5):

[source,bash,role=execute]
----
mkdir -p /tmp/bin
curl -sSfL https://raw.githubusercontent.com/anchore/syft/main/install.sh \
  | sh -s -- -b /tmp/bin v1.18.1
export PATH="/tmp/bin:$PATH"
syft version
----

Generate **both** inventories (SPDX = Python-native teaching artifact; CycloneDX = workshop RHTPA path):

[source,bash,role=execute]
----
cd /tmp/fastapi-lw-poc

syft packages "dir:." -o spdx-json > sbom.spdx.json
syft packages "dir:." -o cyclonedx-json > sbom.cyclonedx.json

ls -la sbom.spdx.json sbom.cyclonedx.json
head -c 300 sbom.spdx.json; echo
head -c 300 sbom.cyclonedx.json; echo
----

Sanity-check:

[source,bash,role=execute]
----
# SPDX JSON often exposes spdxVersion / name / packages
jq '{spdxVersion, name, packages:(.packages|length)}' sbom.spdx.json 2>/dev/null \
  || jq 'keys' sbom.spdx.json | head

jq '{bomFormat, specVersion, components:(.components|length)}' sbom.cyclonedx.json
----

Expect CycloneDX `bomFormat` of `CycloneDX` and a non-zero `components` count. Keep both files in the workspace for Exercise 5 — do **not** commit large SBOMs to Gitea unless your instructor asks.

[IMPORTANT]
====
Showroom terminal home (`/home/lab-user`) is often a root-owned *PersistentVolumeClaim (PVC)*. Keep clones and SBOM files under `/tmp`.
====

== Exercise 5 — Ingest and browse in RHTPA

Reuse the Module 5 Trustify API pattern. Prefer **CycloneDX** for the copy-paste success path. Optionally try **SPDX** afterward—if the API rejects it, that is expected on some workshop builds; keep CycloneDX as the teaching proof.

=== Confirm TPA readiness

[source,bash,role=execute]
----
oc -n trusted-profile-analyzer get configmap rhtpa-ingestion-info \
  -o jsonpath='tpa_ui={.data.server_url}{"\n"}cyclonedx={.data.supported_cyclonedx_version}{"\n"}hint={.data.upload_hint}{"\n"}'

oc -n sso get configmap demo-userinfo-keycloak \
  -o jsonpath='issuer={.data.oidc_issuer}{"\n"}user={.data.workshop_username}{"\n"}'
----

Sign in to the TPA UI Route (not Keycloak `/admin/`) with the workshop `tpa-user` credentials if you want a browser session before the API upload—same caution as Module 5.

=== Ingest CycloneDX (required path)

[source,bash,role=execute]
----
cd /tmp/fastapi-lw-poc
test -f sbom.cyclonedx.json

export OIDC_ISSUER="$(oc -n sso get configmap demo-userinfo-keycloak \
  -o jsonpath='{.data.oidc_issuer}')"
export RHTPA_URL="$(oc -n trusted-profile-analyzer get configmap rhtpa-ingestion-info \
  -o jsonpath='{.data.server_url}')"
export TPA_USER="$(oc -n sso get configmap demo-userinfo-keycloak \
  -o jsonpath='{.data.workshop_username}')"
export TPA_PASS="$(oc -n sso get configmap demo-userinfo-keycloak \
  -o jsonpath='{.data.workshop_password}')"
export CLI_SECRET="$(oc -n trusted-profile-analyzer get secret tpa-realm-cli-clients \
  -o jsonpath='{.data.cli}' | base64 -d)"

TOKEN="$(curl -sk -X POST "${OIDC_ISSUER}/protocol/openid-connect/token" \
  -d grant_type=password \
  -d client_id=cli \
  -d client_secret="${CLI_SECRET}" \
  -d username="${TPA_USER}" \
  -d password="${TPA_PASS}" \
  -d scope=openid \
  | jq -r .access_token)"

curl -sk -X POST \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @sbom.cyclonedx.json \
  -w '\nHTTP %{http_code}\n' \
  "${RHTPA_URL%/}/api/v3/sbom"
----

Confirm HTTP **201** (or another success code) and an SBOM `id` in the JSON body. Do not commit tokens or passwords.

=== Optional — try SPDX upload

[source,bash,role=execute]
----
cd /tmp/fastapi-lw-poc
test -f sbom.spdx.json

# Refresh token if expired, then POST SPDX
TOKEN="$(curl -sk -X POST "${OIDC_ISSUER}/protocol/openid-connect/token" \
  -d grant_type=password \
  -d client_id=cli \
  -d client_secret="${CLI_SECRET}" \
  -d username="${TPA_USER}" \
  -d password="${TPA_PASS}" \
  -d scope=openid \
  | jq -r .access_token)"

curl -sk -X POST \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @sbom.spdx.json \
  -w '\nHTTP %{http_code}\n' \
  "${RHTPA_URL%/}/api/v3/sbom"
----

If SPDX returns an error, keep `sbom.spdx.json` as the Python-native inventory artifact and rely on the CycloneDX upload above for RHTPA browsing.
