This module switches to the *developer golden path*: open *Red Hat Developer Hub (RHDH)*, run the Software Template `lightwell-java-service`, and land the same Lightwell Maven dual-stream project in **your** Gitea organization—then re-run Validated and Remediated proofs against workshop Nexus.

After this module, Modules 4–6 continue from the *scaffolded* tree (same `student_repo_url`), not from the Module 2 template seed contents.

====
If you have not finished xref:module-02-maven.adoc[Module 2]'s Gitea organization exercise (org `lw-@@LW_USER@@` + empty/seeded repos), complete that first. Lab charts start Gitea and your user; **you** own the org and repositories.

== Learning objectives

By the end of this module, you will be able to:

* Open Developer Hub from ConfigMap `demo-userinfo-rhdh` (`rhdh_url`)
* Create a service from Software Template `lightwell-java-service`
* Publish the scaffold to in-cluster *Gitea* under *your* org only (never GitHub / never this workshop monorepo)
* Confirm `pom.xml`, `settings.xml`, `tools/osv-eval/`, and `.tekton/` at the Gitea repo root
* Re-run Maven Validated and Remediated resolution/consumption proofs on the scaffold

== Exercise 1 — Discover RHDH and Gitea URLs

In the Showroom terminal, read the fields you need (not the whole ConfigMap YAML):

[source,bash,role=execute]
----
oc -n rhdh get configmap demo-userinfo-rhdh \
  -o jsonpath='rhdh_url={.data.rhdh_url}{"\n"}software_template={.data.software_template}{"\n"}'

oc -n gitea get configmap demo-userinfo-gitea \
  -o jsonpath='gitea_url={.data.gitea_url}{"\n"}student_gitea_org={.data.student_gitea_org}{"\n"}student_username={.data.student_username}{"\n"}student_repo_url={.data.student_repo_url}{"\n"}'

export RHDH_URL="$(oc -n rhdh get configmap demo-userinfo-rhdh -o jsonpath='{.data.rhdh_url}')"
export GITEA_URL="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')"
export GITEA_ORG="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_gitea_org}')"
export STUDENT_USER='@@LW_USER@@'
export STUDENT_PASS="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')"
export STUDENT_REPO_URL="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')"
export STUDENT_REPO_NAME="$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_name}')"

echo "RHDH:     ${RHDH_URL}"
echo "Gitea:    ${GITEA_URL}"
echo "Org:      ${GITEA_ORG}"
echo "User:     ${STUDENT_USER}"
echo "Repo:     ${STUDENT_REPO_NAME}"
echo "App URL:  ${STUDENT_REPO_URL}"
----

Expect lines like `RHDH: https://backstage-developer-hub-rhdh.apps.<cluster>/` and `Gitea: https://gitea.apps.<cluster>/` (real hosts from your claim — not placeholders).

Open the printed RHDH and Gitea URLs in the browser.

* *RHDH* — choose *Guest* (workshop auth; do not use GitHub — that provider is not configured).
* *Gitea* — sign in as *pass:q[<span class="lw-student-user">student</span>]* with `student_password` from `demo-userinfo-gitea` when prompted.

== Exercise 2 — Delete the seeded app repo

Module 2 left a seeded app repo at `student_repo_url` (`lw-<username>/spring-boot-lw-poc`). The Software Template *creates* a new Gitea repository; it does not force-push over an existing one.

In the *Gitea UI*:

. Open organization *`lw-@@LW_USER@@`* → repository *`spring-boot-lw-poc`*
. *Settings* → *Danger Zone* → *Delete This Repository*
. Type the repository name to confirm and delete

Or from the Showroom terminal (API delete; uses your student credentials):

[source,bash,role=execute]
----
: "${GITEA_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.gitea_url}')}"
: "${GITEA_ORG:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_gitea_org}')}"
export STUDENT_USER='@@LW_USER@@'
: "${STUDENT_PASS:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_password}')}"
: "${STUDENT_REPO_NAME:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_name}')}"

curl -sk -o /dev/null -w "%{http_code}\n" -u "${STUDENT_USER}:${STUDENT_PASS}" \
  -X DELETE "${GITEA_URL}/api/v1/repos/${GITEA_ORG}/${STUDENT_REPO_NAME}"
----

Expect HTTP `204`. A `404` means the repo is already gone—continue.

== Exercise 4 — Clone the scaffold and prove Maven streams

[source,bash,role=execute]
----
: "${STUDENT_REPO_URL:=$(oc -n gitea get configmap demo-userinfo-gitea -o jsonpath='{.data.student_repo_url}')}"

rm -rf /tmp/spring-boot-lw-poc
git clone "${STUDENT_REPO_URL}" /tmp/spring-boot-lw-poc
cd /tmp/spring-boot-lw-poc

ls -la pom.xml settings.xml
ls tools/osv-eval && ls .tekton

export LIGHTWELL_NEXUS_URL="https://$(oc -n lightwell-repo get route nexus -o jsonpath='{.spec.host}')"
export MVN_LOCAL='-Dmaven.repo.local=/tmp/m2'
----

Confirm the scaffold includes lab assets at repo root: `pom.xml`, `settings.xml`, `tools/osv-eval/`, `.tekton/`.

=== Validated resolution + consumption

[source,bash,role=execute]
----
mvn $MVN_LOCAL -s settings.xml dependency:get \
  -Dartifact=org.springframework:spring-core:5.3.18 \
  -Plightwell-validated \
  > /tmp/mvn-scaffold-validated-get.log 2>&1

grep -E 'Downloading from lightwell-java-validated|Downloaded from lightwell-java-validated|BUILD SUCCESS|BUILD FAILURE' \
  /tmp/mvn-scaffold-validated-get.log

mvn $MVN_LOCAL -s settings.xml -Plightwell-validated clean verify \
  > /tmp/mvn-scaffold-validated-verify.log 2>&1

grep -E 'Downloading from lightwell-java-validated|BUILD SUCCESS|BUILD FAILURE' \
  /tmp/mvn-scaffold-validated-verify.log | tail -20
----

=== Remediated resolution + consumption

[source,bash,role=execute]
----
mvn $MVN_LOCAL -s settings.xml dependency:get \
  -Dartifact=org.springframework:spring-core:5.3.18.rhlw-00003 \
  -Plightwell-remediated \
  > /tmp/mvn-scaffold-remediated-get.log 2>&1

grep -E 'Downloading from lightwell-java-remediated|Downloaded from lightwell-java-remediated|BUILD SUCCESS|BUILD FAILURE' \
  /tmp/mvn-scaffold-remediated-get.log

mvn $MVN_LOCAL -s settings.xml -Plightwell-remediated,lightwell-remediated-pins clean verify \
  > /tmp/mvn-scaffold-remediated-verify.log 2>&1

grep -E 'Downloading from lightwell-java-remediated|\.rhlw-|BUILD SUCCESS|BUILD FAILURE' \
  /tmp/mvn-scaffold-remediated-verify.log | tail -30
----

Teaching proofs match Module 2: repository ids `lightwell-java-validated` / `lightwell-java-remediated`, and Remediated coordinates carrying `.rhlw-*`.
